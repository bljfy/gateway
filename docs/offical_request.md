题目
类别	面向大模型推理服务的国密安全网关软件设计实现
	■	软件设计 □硬件制作 □工程实践 □密码应用 □其它
典型场景业务需求	政务、能源、金融等行业正在将内部知识库和业务数据接入大模型推理服务。调用链路通常跨越终端、网关和推理平台，提示词、检索片段及模型输出可能包含敏感信息。参赛团队需设计并实现一套国密安全网关软件，在不改变上层推理接口的前提下，为客户端与推理服务建立安全会话，防止请求和响应在传输过程中被窃听、篡改或重放，并对会话密钥进行规范管理。
题目设计考虑	题目难度适中，允许调用成熟的国密算法库，不要求自行实现底层密码算法或完成形式化安全证明。题目主要考查客户端与服务端程序设计、国密算法正确使用、会话与密钥管理、异常处理、测试和性能分析能力。团队需提交可运行的软件原型、测试脚本和设计文档。

创新要求	参赛团队应实现客户端、国密安全网关和推理服务端模拟程序，并满足以下功能、性能和安全性要求：
1、使用SM2证书或预置公钥完成通信实体身份认证及会话密钥保护；使用SM4保护提示词、检索片段和模型输出，并采用SM4认证加密模式或HMAC-SM3校验报文完整性；
2、实现会话建立、数据传输和会话关闭流程。每条业务报文应包含会话标识、序列号或时间戳等必要信息，能够识别报文篡改和重复报文；认证或校验失败时不得继续处理业务数据；
3、实现会话密钥生成、存储、使用、更新和销毁。算法参数、密钥有效期和日志级别可通过配置文件设置；日志不得记录明文密钥、完整提示词或完整模型输出；
4、提供自动化测试，至少覆盖正常通信、密文篡改、报文重放、会话超时、证书失效或公钥错误等情况，并输出测试步骤、输入数据和判定结果；
5、在同一软硬件环境下，分别完成不少于100次会话建立测试，并使用1 KB和16 KB两组业务载荷测试数据传输；报告平均握手时延、平均吞吐量、CPU占用和峰值内存。参赛作品还应与一种公开的安全通信方案或开源网关进行功能和性能对比，说明本方案的优势与不足。
创新要求：作品可在配置管理、密钥安全存储、批量连接处理、隐私化日志、安全状态展示或易部署性等方面选择一个方向改进，并提供测试结果说明改进效果。创新内容应建立在基本功能正确、安全边界清楚的基础上。
