# Python 编码规范

## 模块与接口

- 源码放在 `src/`，按协议处理、密码接口、会话管理、配置、业务和审计职责拆分。架构及模块布局见 [实现方案](implementation_plan.md)。
- 公共接口提供类型标注和必要说明，异常有明确处理路径。优先使用具体类型、`Protocol`、泛型或经过校验的数据模型；确需 `typing.Any` 时限制范围并说明原因，不取消检查来掩盖问题。
- 仅有一个调用点的一行辅助函数优先内联；有独立语义或边界职责的函数可以保留。
- 导入放在模块顶部；可选依赖或循环依赖确需延迟导入时，先审视模块设计并记录理由。
- 可调整行为通过统一默认配置和配置入口管理，不在业务逻辑中散落硬编码判断。
- 包内资源通过统一函数和 `importlib.resources` 访问，不依赖工作目录或开发机绝对路径；原生动态库按部署配置加载。
- 使用外部 API 前核查实际安装版本的源码、类型存根或对应版本官方文档，不猜测签名。依赖变更遵循 [依赖管理](dependencies.md)。
- 生成文件通过修改生成器或输入后重新生成，与生成器一同提交并检查差异，不手工修改或夹带无关输出。

## 安全与行为边界

密码运算使用成熟库，不自行实现底层算法。身份、报文认证、密钥和日志的具体设计见 [实现方案](implementation_plan.md)。真实密钥、凭据和敏感业务数据不得进入 Git；日志及异常输出不得包含明文密钥、完整提示词或完整模型输出。

删除看起来有意设计的代码或功能前先询问用户。保持已有协议及数据契约，不主动增加未要求的兼容层；破坏性变更说明影响和迁移方式。

## 静态检查

首次实现代码时在 `pyproject.toml` 配置 Ruff、mypy，按依赖管理规范固定版本。代码修改后执行：

```powershell
uv run --locked ruff check src test
uv run --locked ruff format --check src test
uv run --locked mypy src
```

完整查看输出并处理错误和警告，不截断诊断或弱化类型约束。静态检查不替代 [测试验证](testing.md)。
