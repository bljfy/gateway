# 题目要求与项目实现

更新日期：2026-10-21。当前接口契约为 2.0，握手为 v2。测试结果统一见[测试报告](integration_report.md)。

## 项目实现

客户端通过国密网关连接模型适配器，由适配器调用 DeepSeek 或 OpenAI-compatible 服务。客户端→网关、网关→适配器分别建立独立国密会话；适配器→模型服务使用 HTTPS。普通回答和流式输出均沿原路径返回。

| 题目要求 | 当前实现 | 验证依据 |
| --- | --- | --- |
| 身份认证与业务保护 | 预置 SM2 双公钥、双向签名、SM2 密钥传送、SM4-GCM 记录保护 | 真实密码库与双链路测试；错误公钥和失效信任被拒绝 |
| 会话建立、传输与关闭 | 密钥确认、认证 READY、会话 ID、方向与严格序号、认证关闭 | 篡改、重放、跨会话、反射、超时和取消测试 |
| 密钥管理、配置与日志 | 安全随机生成、方向独立密钥、期限和使用预算、轮换与释放、配置校验、白名单日志 | 生命周期、非法配置、敏感标记和审计故障测试 |
| 自动化测试与结果输出 | pytest 单元/集成测试，合成输入和故障注入，JUnit 与 JSON 证据 | 本轮 541 通过、6 平台相关跳过、1 外部模型用例未执行 |
| 性能与公开方案对照 | 相同三进程业务链路，国密/TLS 同时启用恢复和池，两种载荷、四档并发 | 64 档、1,371,209 次成功请求、0 次业务失败；800 个恢复握手样本 |

完整握手材料为 104 字节：双向 SM4 密钥 32 字节、nonce 前缀 8 字节、握手确认密钥 32 字节、恢复秘密 32 字节。流量密钥留在进程内，恢复秘密通过本地加密存储保存。细节见[安全协议](protocol.md)、[会话恢复说明](session_resumption.md)和[公共接口](interfaces.md)。

## 工程特色

- **隐私审计**：只接纳固定事件和有限元数据，区分业务与安全事件容量；审计异常时限制新业务接入。
- **恢复与连接复用**：支持跨客户端进程恢复、凭据到期与撤销；连接池按寿命、记录及字节预算决定复用或淘汰。
- **安全状态可视化**：三角色 WebUI 提供配置、连接观察和协议故障注入，便于验证异常拒绝与资源清理。

这些特色属于面向推理场景的工程整合，不代表新密码算法或强于 TLS 的安全证明。日志和审计不记录业务正文；可信本机网关操作者仍可通过受保护的 WebUI 详情查看限量内存对话。

## 与 TLS 1.3 的比较结论

项目的优势是已贯通国密安全通信与推理管理流程。TLS 基线复用同一业务层，因此审计、分片和限额不能被当作 TLS 缺少的能力。最新对照中，审计开启、10 并发普通请求的 1 KiB/16 KiB 双向吞吐分别为国密 1.67/21.82 MiB/s、TLS 1.81/51.49 MiB/s，TLS 在这些档位更快。

当前方案采用 SM2 密钥传送，尚无前向保密，也未实现 SM2 证书链、CRL/OCSP 和生产密钥托管。后续可从临时密钥协商、标准协议适配与密码调用效率进一步完善。本轮结果仅代表 Windows 本机替身负载；真实模型、跨主机、Linux 当前版本和生产容量仍需专项验收。
