# 开发流程

## 目录职责

| 位置 | 内容 |
| --- | --- |
| `docs/` | 规范、需求、设计、使用说明与验证报告 |
| `src/` | Python 源码 |
| `test/` | pytest 测试、夹具与可复用合成数据 |
| 根目录 | 项目配置、依赖声明、锁文件和 Agent 入口 |
| `.github/workflows/` | CI/CD 工作流 |

任务范围和阶段验收由 [实现方案](implementation_plan.md) 定义；具体编码、依赖、测试和交付分别遵循 [编码规范](coding.md)、[依赖管理](dependencies.md)、[测试规范](testing.md) 与 [CI/CD 规范](ci_cd.md)。

## 任务闭环

1. 检查 `git status`、分支及 `git worktree list`，保留其他任务的修改。每项任务在独立 worktree 和 `codex/` 分支开展；适合本任务的现有 worktree 可以复用。
2. 从明确基准创建 worktree，例如 `git worktree add -b codex/task-name .worktrees/task-name main`。按依赖管理规范准备环境，各 worktree 不共享虚拟环境或可变运行数据。
3. 阅读相关规范及完整文件，完成实现、对应测试和文档同步。
4. 代码修改运行编码规范中的静态检查和测试规范中的验证；纯文档修改检查内容、链接、路径、示例与 `git diff --check`。失败须修复；工具或环境未就绪时明确记录，不能报告检查通过。
5. 编码、测试及文档同步完成后，独立调用一个未参与本次实现的 subagent，按下述审查要求 review 本任务完整 diff；处理反馈并完成必要复审后再提交。纯文档修改也执行此步骤。
6. 每次完成逻辑完整、可验证的修改都创建 `git commit`，只暂存本任务明确路径。提交前检查状态和暂存差异，确认提交内容与已审查版本一致，源码、测试与相关文档一同提交。
7. 按项目流程集成已验证提交；冲突处理后重新验证受影响内容，产生的新 diff 再交由独立 subagent 审查。交付说明记录提交哈希、变化、实际检查结果、审查结论及未解决项。
8. 确认已集成、无未提交修改及需保留产物后，使用 `git worktree remove <path>` 清理任务 worktree。

`.worktrees/`、`.venv`、缓存、日志和运行产物加入忽略规则，不提交真实密钥或敏感数据。

## 独立 diff 审查

- 审查者使用独立 subagent，不由实现者自审替代，也不参与本次实现。提供用户需求、任务 worktree、基准提交、变更范围和实际验证结果。
- 审查覆盖相对基准的完整任务变更，包括已提交、暂存、未暂存及新增文件中的源码、测试和文档；通过 diff 定位后阅读必要的完整文件及相关规范。不审查或修改其他任务的内容。
- subagent 只读审查，不修改文件、暂存、提交或切换分支。重点检查正确性、安全边界、回归风险、测试缺口及文档一致性，不以风格偏好代替问题证据。
- 每条问题给出严重程度、文件与行号、触发条件或依据及建议；没有发现问题时明确给出结论，并列出未验证项。
- 实现者处理有效问题；不采纳的意见说明依据，有影响交付的问题未解决前不得提交。修改后重新执行受影响检查，再由独立 subagent 复审最终 diff，避免只审查修复前版本。
- subagent 不可用或审查未完成时，记录阻塞并等待处理，不将自审标为独立审查完成。

## 文档同步

每次修改代码、测试、依赖、配置或工作流程，都同步更新对应文档。功能与架构更新实现方案；接口或协议更新专项设计与示例；环境和配置更新安装使用说明；测试与性能更新步骤、输入、判定及实测报告。

规则只在所属文档维护，其他位置引用。保留原始需求，区分设计目标、已实现状态和验证结果；新增专项文档时更新入口，避免失效链接。

用户可见变更在 `docs/changelog.md` 的 `Unreleased` 下记录，首次需要时创建。按需使用“破坏性变更、新增、变更、修复、移除”小节，先完整阅读并追加，不重复标题，不改写已发布历史。关联问题单或 PR 使用真实编号和链接，破坏性变更说明迁移方法。

## 提交与协作保护

提交格式为 `类型(可选模块): 修改说明`，类型采用 `feat`、`fix`、`refactor`、`test` 或 `docs`，模块使用本项目实际名称，如 `client`、`gateway`、`server`、`protocol`。关闭问题单逐项使用 `fixes #123` 或 `closes #123`。

只提交本会话实际修改文件，使用 `git add <明确路径>`。发现他人的暂存内容时停止提交，改用独立 worktree，不更改他人的暂存状态。不使用 `git reset --hard`、`git checkout .`、`git clean -fd`、`git stash`、`git add -A`、`git add .`、`git commit --no-verify`，不强制推送。

合并或变基只解决自己修改文件的冲突；其他文件冲突时停止集成，安全中止操作并询问用户，保留他人修改。

## 回滚与数据

已提交变更优先用 `git revert <commit>` 回滚，保留历史，同步文档并验证行为。Git 保存源码、配置示例、文档和合成测试数据；运行数据单独备份。修改持久化数据或格式前备份，并提供迁移、恢复及验证步骤。测试数据复用规则见测试规范，部署产物回滚见 CI/CD 规范。

临时脚本写入独立文件后运行，不在 PowerShell 中嵌入大段脚本；使用系统临时目录 `[System.IO.Path]::GetTempPath()`。结束后只清理本任务临时文件，删除或移动前核实绝对路径及范围。
