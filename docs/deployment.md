# 本地部署与回滚

本轮交付为单机三程序原型，使用独立 SM2 身份和两段 SM4-GCM 安全会话。环境准备见 [开发指南](developer_guide.md)，生成配置、启动及停机的完整命令见 [使用说明](usage.md)。生产环境流程由 [CI/CD 规范](ci_cd.md) 定义。

## 启动与检查

1. 固定源码提交、Python 3.12.11、uv 0.8.22 和 `uv.lock`，构建并验证 GmSSL 3.1.1 清单。
2. 用 `init-demo` 创建尚不存在的本地目录。检查三个端口空闲、目录仅授权当前用户，保存配置与私钥的受控备份。
3. 启动模拟器，再启动网关，等待各自 `ready`。使用客户端发起普通和流式合成请求，核对确定性响应。
4. 读取本机 `/metrics`，确认成功计数和审计健康；检查 JSONL 只包含允许的事件字段。完整自动验证见 [整合报告](integration_report.md)。

服务不提供自动重试或配置热更新。模拟器不是实际模型平台；目前每次请求创建新上游会话。原型信任模式不提供前向保密，安全性质和内存清理边界见 [协议说明](protocol.md)。本机指标不可经代理公开。

## 停机与恢复

使用 Ctrl+C 或启动时指定的停止文件，先停网关，再停模拟器。等待进程退出，确认原监听端口释放、审计已排空；停止文件仍在时服务会立即结束，重启前删除它。

恢复同一版本时复用受控配置目录与经校验原生库。不要对已有目录重复 `init-demo`，它会拒绝覆盖身份；需要新身份时创建新目录，并同步三端公钥信任。重建身份会使旧会话失效，不能在运行中只替换一个端的配置。

回滚源码使用 `git revert <整合提交>` 或部署事先保留的指定提交产物；回滚前停止服务并备份审计及配置，回滚后重新执行静态检查、全量本地测试和三程序合成请求。旧版本缺少本轮 CLI 时，不能用新角色配置直接启动旧入口，应恢复该版本的启动方式。备份包含口令与私钥，需要与公开测试报告分开保存。

本轮验证了独立进程正常停机和资源释放；尚未执行生产服务器部署、版本化产物发布或真实环境回滚演练。

## 生产验收记录

截至 2026-10-05，生产环境仍待验收。当前 `.github/workflows/cd.yml` 执行 CI、标签/版本校验、wheel/sdist 构建、来源与文件 SHA256 记录及 Actions 产物保存。它没有部署目标、GitHub Environments 审批、测试环境提升、生产凭据、失败自动恢复或选择历史产物的回滚任务；不能以工作流名称或构建成功代替上线证明。

本地已使用 `uv build --no-sources --offline` 构建 0.1.0 wheel/sdist，并在全新虚拟环境离线安装该 wheel 和唯一运行依赖 `gmssl-python==2.2.2`。确认导入来自安装目录后，三个 CLI 使用候选环境完成普通 1 KiB/16 KiB 与流式 70000 字节请求，成功指标及成功审计均为 3，正常停机。证据为 `artifacts/wheel-smoke.json`。此次复用单独提供且已校验的本机 GmSSL DLL，未生成完整平台运行包；候选构建尚未关联发布标签、目标环境或生产审批。
