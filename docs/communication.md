# 沟通与协作规范

## 表达与判断

- 回复、注释、提交及外部评论使用简洁、直接的技术语言，不使用表情符号或寒暄填充；无法避免的术语先解释再使用。
- 用户提问时先回答再修改；回应反馈或分析时先说明同意、不同意或部分同意及理由，再说明变更。
- 非简单设计按问题、具体例子或简短执行过程、解决方案解释，说明必要性和可选扩展，优先描述可观察行为。
- 无法判断用户意图或任务范围的歧义时再澄清。

## 审查与外部渠道

审查 PR 使用只读元数据和差异查询，不擅自切换当前 worktree 分支；完整文件通过 `git show <ref>:<path>` 或任务临时文件读取。

向问题单、PR 或其他外部渠道发布内容须有用户明确授权。多行正文写入 UTF-8 临时文件，通过 `--body-file` 等文件参数提交；采用用户的语言和本仓库确实适用的标签。如任务要求 AI 生成声明，使用指定文本。

多人修改、暂存保护和冲突处理见 [开发流程](development.md)。
